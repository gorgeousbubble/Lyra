# Lyra 智能手表 — 硬件设计方案

本文档定义**只属于 Lyra 手表本身**的硬件，剥离 MAPS-K64 / MAPS-DOCK 开发套件遗留部分。
架构图见 `architecture.svg`，开发板现状引脚表见 `../reference/devkit_pinmap.md`。

## 结论先行

Lyra 的全部手表功能只需要 **5 个器件**：

| 器件 | 接口 | 不可删的理由 |
| --- | --- | --- |
| SSD1306 OLED 128×64 | 软件 I2C，0x3C | **唯一的 UI 屏**，全部 16 个菜单都画在它上面 |
| MPU6050 | 软件 I2C，0x68 | 计步、睡眠、跌倒、倾斜报警、姿态、陀螺表盘 |
| MAX30102 | 软件 I2C，0x57 | 心率、血氧、健康评分 |
| 蜂鸣器 / 振动马达 | 单 GPIO | 闹钟、跌倒报警、倾斜报警 |
| 按键 × 4 | 4 GPIO | 菜单导航的全部所需 |

加上 W25Q80（可选）、两个晶振、SWD 和一套**全新的电源系统**，信号引脚需求约 **27 根**，
而当前开发板占用约 80 根。

## 为什么能砍掉这么多 — 固件证据

### 三块屏里只有一块在做 UI

| 显示器 | app 层调用情况 | 判定 |
| --- | --- | --- |
| SSD1306 OLED 128×64 | 每个 `Render_*()` 都以 `Oled_I2C_Draw_Picture_128x64()` 收尾 —— `watch.c` 22 处、`activity_history.c:473`、`adc_scope.c:351`、`attitude3d.c:267`、`freefall.c:324`、`gyro_dash.c:235`、`health_monitor.c:250`、`health_score.c:283`、`sleep_monitor.c:310`、`tilt_alarm.c:207`；`pedometer.c:168-209` 直接调 `Oled_I2C_Put_Str_*` | **唯一 UI 屏** |
| ILI9341 320×240 彩屏（FlexBus） | 全 app 层只有 2 处：`init.c:96` 初始化、`main.c:164` 开机贴一张 `Mitsuha.bmp`，之后再也不刷 | **可删** |
| ST7565R 128×64 LCM（SPI2） | `main.c:342` 每轮主循环调 `MAPS_Dock_Rocker_Key_LCM_Control()`，内容是 5 页调试变量（PIT0 计数、ADC 原始值、MPU 六轴、RTC 字段、MAX30102 原始值）；`conf.c:45-53` 死机时打印 IRQ 名 | **开发期工具，可删** |

删掉彩屏一并省掉：**29 个 FlexBus 引脚**、`LCDC_Freescale_Logo[153600]` 的 **150 KB flash**、
SD 卡 + FatFs、外部 SRAM（`0x8000_0000` 窗口只被 `MAPS_LCDC_BMP()` 内部用过，app 层零访问）。

> **一个必须注意的耦合**：OLED 用的位图常量来自 LCM 的字库文件。
> `maps_dock_key.c:345` 把 `LCM_Freescale_logo`（定义在 `board/inc/maps_dock_lcm_lib.h`）
> 喂给了 `Oled_I2C_Draw_BMP_128x64()`，`watch.c` 各 `Render_*` 的 `dial`/`digit`/`item` 实参同样来自那里。
> **删 LCM 驱动可以，`maps_dock_lcm_lib.h` 的位图表（约 43 KB）不能一起删。**

### 摇杆和 LED 对手表功能零贡献

| 输入 | 实际行为 |
| --- | --- |
| 摇杆 Select（PTA4）/ Left（PTA25）/ Right（PTA24） | 只用于进入和翻页 LCM 调试页 |
| 摇杆 Up（PTA27）/ Down（PTA26） | `maps_dock_rocker.c:101-110` 里只有一句 `Rocker_Key_Delay(500)`，**没有任何功能** |
| LED × 4（PTB4-7） | `it.c:196` 在 PIT0 的 100 ms 分支整体翻转（心跳指示）；`conf.c:55-68` 死机时闪烁。没有任何"步数达标/低电量/心率异常"语义 |

菜单导航实际只用 KEY0-KEY3 四个键（`maps_dock_key.c:346/374/384/403`）。
顺带一提：摇杆 Select 接在 **PTA4 = NMI** 引脚上，新板不要再这么接 —— 不过摇杆本来就要删。

### 两个菜单项与手表无关

`adc_scope`（把 K64 两根裸模拟脚当双通道示波器）和 `gyro_dash`（陀螺原始值波形）
都注册在菜单里（`main.h:57,64`），是用户可见项，但属于开发板演示性质。
**删掉 `adc_scope` 正好把 `ADC0_DP0` 让给电池电压检测。**

### 存储严重过剩

W25Q80 是 1 MB，现在用 13 个扇区（52 KB 地址空间）承载 **70 字节**有效配置：

| 内容 | 扇区 | 字节 |
| --- | --- | --- |
| 闹钟列表（8 条） | 0 | 16 |
| 12/24 小时制 | 1 | 1 |
| 7 天步数历史 | 2 | 37（36 + 1 CRC） |
| 步数目标 / 步长 / 睡眠目标 / 蜂鸣器开关 / 倾斜阈值 / 响铃时长 / 计步防抖 / 心率区间 / 跌倒灵敏度 / 睡眠灵敏度 | 3 – 12 | 各 1–2 |

`prj/IAR/config files/MK64FX512_FLASH.icf:17-18` 确认 MK64FX512 带 **128 KB FlexNVM @ 0x1000_0000**，
放 70 字节配置绰绰有余 ⇒ 改走 FlexNVM 即可省掉一颗芯片和 4 个引脚（决策 2 已采纳）。
具体改哪里见后文「决策 2 的实际改动量」—— 只需换掉 3 个函数的后端。

## 引脚分配

### 封装决策：100-LQFP（已定）

K64 的 100-LQFP 对应 `VLL` 后缀。14 × 14 mm，比 144-LQFP 的 20 × 20 mm 小一圈，
按上面 27 根信号的需求来看引脚数绰绰有余。

**但它让「零固件改动」不再成立。** 100 脚比 144 脚少 44 个引脚，
Kinetis 缩减封装时砍掉的通常是各端口的高位引脚 —— 而 Lyra 现在的引脚恰好大量落在高位段：

| 现引脚 | 用途 |
| --- | --- |
| PTA28 / PTA29 | MPU6050 软件 I2C |
| PTE26 / PTE28 | OLED 软件 I2C |
| PTE10 / PTE11 | MAX30102 软件 I2C |
| PTD11 – PTD14 | SPI2 + W25Q80 |
| PTC14 / PTC15 | UART4 |

所以引脚必须重新分配。好消息是代价比看起来小得多。

### 27 个信号里有 13 个完全不受引脚复用约束

`chip/inc/gpio.h:47` 的 `GPIO_Init(PTXn, GPIO_CFG, uint8)` 接受任意 `PTXn`，
`chip/inc/gpio_cfg.h` 为 5 个端口的全部 32 位生成了统一宏。
所有位带（软件模拟）信号因此可以搬到**任何**可用引脚上：

| 信号 | 数量 | 现引脚 | 约束 |
| --- | --- | --- | --- |
| OLED SCL / SDA | 2 | PTE26 / PTE28 | 无 —— 纯 GPIO 位带 |
| MPU6050 SCL / SDA | 2 | PTA29 / PTA28 | 无 |
| MAX30102 SCL / SDA | 2 | PTE10 / PTE11 | 无 |
| MAX30102 INT | 1 | PTA10 | 无（轮询读取，未用中断） |
| MAX30102 LED 驱动 | 1 | PTA7 | 无 |
| 按键 KEY0-3 | 4 | PTB21/22/23/20 | 无 |
| 蜂鸣器 / 马达 | 1 | PTE7 | 无 |
| **小计** | **13** | | **可自由重排** |

三条 I2C 保持独立位带**不只是为了省事**：OLED 整屏刷新是 1024 字节，
与 100 Hz 的 MPU6050、MAX30102 读取挤在同一条总线上会明显争用
（1024 字节在 400 kHz 硬件 I2C 上约 23 ms）。三条独立位带总线天然避开了这个问题。

### 受约束的 14 个

备选引脚来自 `chip/inc/port_cfg.h` 各宏的行尾注释。

| 信号 | 数量 | 备选引脚 |
| --- | --- | --- |
| SPI2 SCK / MOSI / MISO / PCS0 | 4 | PTD12/13/14 + PTD11，**或** PTB21/22/23 + PTB20 |
| UART4 RX / TX | 2 | PTC14 / PTC15，**或** PTE25 / PTE24 |
| ADC0_DP0（电池检测） | 1 | 专用模拟脚，无备选 |
| EXTAL / XTAL | 2 | 专用 |
| EXTAL32 / XTAL32 | 2 | 专用 |
| SWD_CLK / SWD_DIO | 2 | PTA0 / PTA3 固定 |
| RESET_b | 1 | 专用 |

### 一个撞车问题，正好支持删掉 W25Q80

SPI2 的**唯一备选引脚组是 PTB20 – PTB23**，而这正是 4 个按键现在的位置
（`board/src/maps_dock_key.c:43`）。如果 100-LQFP 上 PTD11 – PTD14 不全可用，
W25Q80 就得挪到 PTB20-23，和按键直接冲突。

按键是纯 GPIO，让路容易，但更干脆的做法是**直接删掉 W25Q80，改用片内 FlexNVM**：

- SPI2 整个不用了，省 4 个受约束引脚
- 省一颗芯片、一组走线、一个封装占位
- 70 字节配置放 128 KB FlexNVM 绰绰有余（`MK64FX512_FLASH.icf:17-18`）

这样受约束信号从 14 降到 **10**，剩下的全是无可替代的专用脚（晶振 ×4、SWD ×2、
RESET、ADC）加一路可选调试串口。

**这就是决策 2 最终选 FlexNVM 的原因。** 上面那张「受约束的 14 个」表因此只剩 10 项 ——
SPI2 那 4 根已经不存在了，下文的引脚分配表反映的是删掉之后的结果。

### 最终引脚表怎么定

因为 13 个位带信号可以任意摆放，引脚表应该**按 PCB 布线便利性倒推**，
而不是沿用开发板的历史分配。建议顺序：

1. 先锁定不可动的：晶振 ×4、SWD ×2、RESET、ADC0_DP0
2. 再定调试串口：优先 PTC14 / PTC15，不可用则换 PTE25 / PTE24
3. 剩下 13 个位带信号按走线最短原则分配 —— **让器件在板上的物理位置决定引脚，而不是反过来**

## 引脚分配表（建议方案）

### 第一类：锁定，不可动

| 信号 | 引脚 | 说明 |
| --- | --- | --- |
| SWD_CLK | `PTA0` | 固定 |
| SWD_DIO | `PTA3` | 固定 |
| RESET_b | 专用脚 | 固定 |
| 50 MHz 有源晶振输入 | `EXTAL` | `XTAL` 悬空 |
| 32.768 kHz 无源晶体 | `EXTAL32` / `XTAL32` | 无需外部电容 |
| 电池电压检测 | `ADC0_DP0` | 专用模拟脚 |

这些在任何封装上都必然存在（电源、时钟、调试、模拟是基本盘），不需要查手册。
`PTA1` / `PTA2`（JTAG TDI/TDO）不接，省掉。

### 第二类：一项需要确认

| 信号 | 首选 | 备选 |
| --- | --- | --- |
| UART4 RX / TX | `PTC14` / `PTC15` | `PTE25` / `PTE24` |

这是删掉 SPI2 之后**唯一还受引脚复用约束、且落在高位段**的信号。
只是调试测试点，万一两组都不可用，直接不引出也能跑。

### 第三类：13 根位带信号 — 建议分配

分配规则，按优先级：

1. **落在硬件 I2C 外设的引脚上** —— 三条总线将来想从位带升级成硬件 I2C 时不用改板
2. **三条总线分在三个不同端口** —— 三个器件在板上物理分离，走线互不干扰
3. **优先低位引脚** —— 缩减封装砍掉的通常是各端口高位
4. 避让专用脚（见下面的避让清单）

| 信号 | 建议引脚 | 选它的理由 |
| --- | --- | --- |
| OLED SCL | `PTB0` | `port_cfg.h:92` 列为 `I2C0_SCL` 备选 |
| OLED SDA | `PTB1` | `port_cfg.h:93` 列为 `I2C0_SDA` 备选 |
| MPU6050 SCL | `PTA12` | `port_cfg.h:100` `I2C2_SCL` |
| MPU6050 SDA | `PTA11` | `port_cfg.h:101` `I2C2_SDA` |
| MAX30102 SCL | `PTC10` | `port_cfg.h:96` `I2C1_SCL` |
| MAX30102 SDA | `PTC11` | `port_cfg.h:97` `I2C1_SDA` |
| MAX30102 INT | `PTB2` | 纯 GPIO，低位 |
| MAX30102 LED 驱动 | `PTB3` | 纯 GPIO，低位 |
| KEY0 进入/确认 | `PTC0` | 纯 GPIO，四键连号便于侧面排布 |
| KEY1 返回 | `PTC1` | |
| KEY2 上一项/减 | `PTC2` | |
| KEY3 下一项/加 | `PTC3` | |
| 振动马达 | `PTC4` | 纯 GPIO |

规则 1 是这张表最值得说的地方：三条软件 I2C 分别落在 **I2C0 / I2C1 / I2C2** 的
物理引脚上。现在仍然跑位带（避免总线争用，见上文 OLED 整屏 23 ms 的测算），
但将来任何一条想换成硬件外设，改宏即可，**板子不用重新打**。

### ⚠ 这张表还缺一个输入

上面三类里，第一类确定，第二类只影响一个可选的调试口。
**第三类的 13 根引脚是按上述规则推的，不是从 100-LQFP 引脚表查出来的。**

规则 3（低位优先）是个合理的经验判断，不是验证过的事实。
`PTA11` / `PTA12` 和 `PTC10` / `PTC11` 属于中段，最需要确认。

好消息是这 13 根全是纯 GPIO，而且**换引脚连驱动头文件都不用改**（见下面的固件工作清单），

## 时钟源 — 两个已查实的结论

这两条直接决定 BOM，而且和我最初画的框图不一样。

### 50 MHz 必须用有源晶振，不是无源晶体

`chip/src/mcg.c` 的 `PLL_Init()` **从未写过 `MCG_C2_EREFS`**（全仓库 grep，
`MCG_C2_EREFS_MASK` 只出现在 `startup/inc/MK64F12.h:8196` 的定义处）。
复位后 EREFS = 0，含义是**选择外部参考时钟源，片内振荡器放大电路被旁路**。

| 结论 | 说明 |
| --- | --- |
| 器件类型 | **有源晶振（oscillator can）**，3.3 V，CMOS 输出 |
| 接法 | 输出 → `EXTAL`，`XTAL` 脚**悬空** |
| 负载电容 | **不需要** —— 无源晶体才需要 |
| 额外需要 | 晶振自己的 VDD 去耦电容 |

无源晶体在 EREFS = 0 下不会起振。这条如果搞错，板子上电就不跑。

顺带一提，`mcg.c:372` 写了 `MCG_C2_RANGE(1)`，注释说「高频范围 3-8 MHz」——
在 EREFS = 0 时这个字段没有作用，无害，但说明这段配置是从别处抄来的，
并没有针对 50 MHz 推敲过。下面那条风险同源。

### 32.768 kHz 则相反 —— 用无源晶体

`chip/src/rtc.c:37-41` 设了 `RTC_CR_OSCE` 和 `SC16P`（片内 16 pF 负载电容）。

| 结论 | 说明 |
| --- | --- |
| 器件类型 | **无源晶体**，32.768 kHz |
| 接法 | `EXTAL32` / `XTAL32` |
| 负载电容 | **不需要外部电容** —— 已选片内 16 pF |

### ⚠ 风险：PLL 配置的算术对不上

`MCG_PLL` 表把 `{PRDIV=24, VDIV=26}` 标为 `PLL100`，而 `PLL_Init()` 自己的注释
（`mcg.c:396`）写的公式是 `EXTAL/(PRDIV+1)*(VDIV+16)`。代入算：

```
50 MHz / (24+1) = 2 MHz        ← PLL 参考频率
2 MHz × (26+16) = 84 MHz       ← 不是 100 MHz
```

而 `app/inc/conf.h:29` 告诉固件其余部分 `MK64_CORE_CLK = 100`。如果上面的算术成立，
所有由核心/总线频率推导的东西都会偏约 19% —— DWT 延时、PIT 的「1 ms」、
UART 的 115200 波特率（19% 误差远超串口能容忍的范围）。

我没法把这件事彻底结案，原因是：本仓库的 `MK64F12.h:8223,8231` 把 `PRDIV0`
和 `VDIV0` 都声明为 5 位（掩码 `0x1F`），这是 K60 的 MCG 布局；
而 K64 的 MCG 我记得 `PRDIV0` 只有 3 位（÷1-8）。
两种情况下算出来的频率完全不同，而我没有联网也读不了那份 PDF，无法确认哪个对。

**对画板的影响**：在订 50 MHz 晶振之前，建议先在现有开发板上实测一下主频
（比如用 GPIO 翻转配示波器，或让 PIT 定时 1 秒对表）。如果确认配置有问题，
顺便可以换一个更常见、更便宜的频率（50 MHz 有源晶振比 8/12/16 MHz 贵且难找），
代价是要重算 PRDIV/VDIV。

原型阶段保持 50 MHz 的好处是固件一行都不用动，这是最低风险路径。

## 必须新增的部分 — 电源系统

固件里**完全没有**电源相关代码，这块要从零设计。按决策 5「原型优先」，
拓扑选最简单可靠的那条。

### 电源链

```
USB 5 V ──→ 充电管理 IC ──→ 单节锂聚合物(带保护板) ──┬──→ 3.3 V LDO ──→ 系统
                                                      └──→ 分压 ──→ ADC0_DP0
```

| 环节 | 原型阶段选择 | 要点 |
| --- | --- | --- |
| 输入 | Micro-USB 或 USB-C | USB-C 要加 CC 下拉电阻才能取到 5 V |
| 充电 | 单节线性充电 IC | 充电电流由一只电阻设定，建议 ≤ 0.5C |
| 电池 | 单节锂聚合物，**必须带保护板（PCM）** | 过充/过放/短路保护，安全项不能省 |
| 稳压 | 3.3 V LDO | 见下面的掉压说明 |
| 电量检测 | 两只电阻分压 + 一只滤波电容 → ADC0_DP0 | 分压比按 4.2 V 满量程 < 3.3 V 参考来定 |
| 马达 | 低边 N-MOSFET + 续流二极管 + 就近储能电容 | 决策 4；`beep.c` 的 GPIO 直接驱动栅极 |

### LDO 的掉压代价

锂聚合物从 4.2 V 放到 3.0 V。3.3 V LDO 需要输入高于 3.3 V 加上自身掉压，
所以电池降到约 3.5 V 以下时 3.3 V 轨就失去调节了。

好消息是锂聚合物的放电曲线大部分容量落在 4.2 → 3.5 V 这段，LDO 损失的是尾部一小段
（具体比例取决于电芯和放电倍率）。原型阶段完全可以接受。
要吃满容量得换 buck-boost，多一组电感和更复杂的布局。

### 还需要注意的

| 项 | 说明 |
| --- | --- |
| 去耦 | K64 有多个 VDD 引脚，每个就近一只 100 nF，另加整板 bulk 电容 |
| VDDA / VREFH | 模拟供电要和数字分开滤波，这关系到电量检测的读数精度 |
| VBAT | 原型可直接接 3.3 V。代价是电池耗尽后 RTC 丢时间 —— 要保时间得单独做备份域 |
| 马达回流 | 马达启动电流大，布局时要让它的回流路径远离 MAX30102 和电池分压这两处模拟敏感点 |

电流预算我给不了具体数字 —— K64 在 100 MHz 下的典型电流要查数据手册，
我读不了那份 PDF。需要你取三个数：K64 运行电流、OLED 模块峰值电流、马达启动电流，
三者相加再乘续航小时数，就是电池容量下限。

### ⚠ 续航是这个设计最大的风险

已核实：`LLWU`、`__WFI` 只出现在 `startup/inc/` 的 CMSIS 头文件里，
**`app/` 和 `chip/` 里零调用**。也就是说固件目前：

- 100 MHz 主频常开，没有任何 STOP / VLPS 低功耗模式
- PIT0 / PIT1 各 1 ms 中断常开
- 主循环空转轮询，没有 `WFI`
- OLED 每轮主循环整屏刷新，没有息屏超时
- 100 Hz 位带 I2C 读两个传感器

**不加休眠逻辑，续航是小时级而不是天级。**
这是固件问题，但它直接决定电池容量和外形尺寸，所以必须在画板之前决定：
要么接受短续航做原型，要么先补低功耗代码再定电池。

### 换引脚不需要改驱动 —— 所有位带宏都是 `#ifndef` 可覆盖的

每个位带引脚宏都写成这个形式：

```c
#ifndef OLED_I2C_PORT_INIT_SCL
#define OLED_I2C_PORT_INIT_SCL GPIO_Init(PTE26, GPO, 0)
#endif
```

`#ifndef` 意味着**先定义者胜**。所以新板的引脚图可以集中放在一个新文件里，
在包含驱动头之前引入，驱动头文件一行都不用动：

| 文件 | 宏数量 | 涉及引脚 |
| --- | --- | --- |
| `dev/inc/oled_i2c.h:24-61` | 10 | `PTE26` / `PTE28` |
| `dev/inc/mpu6050.h:61-89` | 10 | `PTA29` / `PTA28` |
| `dev/inc/max30102.h:47-75` | 10 | `PTE10` / `PTE11` |
| `app/inc/health.h:26-42` | 5 | `PTA10` / `PTA7` |
| `app/inc/beep.h:23-32` | 3 | `PTE7` |

合计 38 个宏，全部可覆盖。建议新建 `app/inc/board_pins.h` 放手表的引脚图，
原驱动保持原样 —— 这样开发板和手表板可以共用一套代码，靠编译配置切换。

**唯一的例外**是按键：`board/src/maps_dock_key.c:43` 是 C 数组初始化
`PTXn Key_PTXn[KEY_MAX] = {PTB21, PTB22, PTB23, PTB20};`，不是宏，需要直接改这一行
（或者顺手也改成可覆盖的宏）。

引脚和存储接口都落在宏与函数边界上，这是这套代码的一个优点 —— 换封装、换存储都不用动业务逻辑。

## 遗留问题

**PTA7 引脚冲突。** `app/inc/health.h:29` 把 `IRD` 定义为 PTA7 的 GPIO，`:32` 又把 `RD` 定义成
`FTM0_CH4`，而 `FTM0_CH4_PIN` 正是 PTA7（`chip/inc/port_cfg.h:58`）。
`app/src/health.c:55-57` 先初始化 PWM 再初始化 GPIO，GPIO 覆盖了 PWM ⇒ `RD_Duty` 实际不起作用。
**新板上这里只画一条网络**，并建议顺手修掉固件里的重复声明。

**MCG 分频表疑似继承自 K60。** `chip/src/mcg.c:18` 的注释公式无法还原表中数值；
表项符合 K60 的 `EXTAL/(PRDIV+1)×(VDIV+24)`，按此算 PLL 参考频率为 2 MHz，
低于 K64 手册要求的 8–16 MHz。换晶振或调主频之前务必核对。

**Linker 少用了 64 KB SRAM。** `MK64FX512_FLASH.icf:21-22` 把 SRAM2 算成
`0x20000000 + 64KB×2 = 0x20020000`（128 KB），注释却写 192 KB。
K64 是 64 KB SRAM_L + 192 KB SRAM_U = 256 KB，所以有约 64 KB 没被链接进去。
不影响画板（已识别静态 RAM 只有 16–17 KB），但顺手可以修。

**RAM 占用不紧张。** 已识别静态用量约 16–17 KB / 256 KB，最大单项是 MAX30102 的
SpO2 算法链约 14 KB（500 点数据被复制三份：环形缓冲 → `ir/red_array` → `an_x/an_y`）。
帧缓冲只有 1 KB 且全局共用。**不需要外部 SRAM。**
